QA, QC y testing

QA

Previene defectos desde el proceso.

QC

Verifica el producto ya desarrollado.

Testing

Ejecuta el software para comprobar resultados.

QA previene, QC verifica y las pruebas comprueban.
Aclarar los tres conceptos: QA se enfoca en el proceso y busca prevenir defectos; QC se enfoca en el producto final y detecta defectos en lo desarrollado; testing es una actividad específica que ejecuta el software para verificar si cumple lo esperado. Usar la analogía del restaurante: QA pone reglas y controles para cocinar bien, QC revisa si el plato salió bien y testing prueba el plato para confirmar si tiene buen sabor.

Regresión, humo y sanidad

Regresión

Confirmar que un cambio no dañó lo que ya funcionaba.

Humo

Revisión rápida para saber si lo básico carga.

Sanidad

Validar que una corrección específica funcionó.

Explicar que las pruebas de regresión se usan después de cambios para confirmar que una actualización no rompió funciones anteriores. Ejemplo: si se agrega un campo al módulo de reservas, se revisa que todavía funcione guardar, editar, eliminar, buscar y generar reportes. Las pruebas de humo verifican rápidamente que lo básico funcione: que la app abra, que se pueda iniciar sesión y que las pantallas principales carguen. Las pruebas de sanidad revisan que una corrección específica funcionó. Frase: "Cada cambio debe probarse, porque en software una mejora también puede crear nuevos errores."

QA vs Control de calidad

QA

Busca evitar errores desde el proceso: reglas, orden, estándares y buenas prácticas.

Previene errores

QC

Busca encontrar errores en el producto construido o en una versión que se va a entregar.

Detecta errores
Explicar sin complicarse: QA o aseguramiento de calidad busca prevenir errores desde el proceso. En cambio, el control de calidad busca detectar errores en el producto ya construido o en una versión que se va a entregar. Analogía del restaurante: QA sería tener reglas para cocinar bien, como higiene, recetas, tiempos y orden. Control de calidad sería probar el plato antes de servirlo para verificar que no esté quemado, crudo o mal preparado. Frase: "QA previene errores. Control de calidad detecta errores."

Factores de calidad

También debe ser fácil, rápido, seguro, confiable y fácil de mejorar. Introducir los cinco factores del PDF: usabilidad, rendimiento, seguridad, confiabilidad y mantenibilidad.

Usabilidad

Si el usuario se pierde, el software tiene mala usabilidad.

TikTok

El usuario entiende rápido dónde tocar y qué hacer.

WhatsApp

Mensajes simples, interfaz clara y flujo directo.

Confuso

Demasiados botones, pasos innecesarios y dudas.

Explicar que usabilidad significa qué tan fácil es usar el software. Usar ejemplos: TikTok o WhatsApp son fáciles de usar porque uno entiende rápido qué hacer, dónde tocar y cómo encontrar funciones principales. Analogía: es como un control remoto con demasiados botones; si nadie sabe cuál usar, no es cómodo. Frase corta: "Si el usuario se pierde, el software tiene mala usabilidad."
David

Rendimiento y seguridad

Rendimiento

El software debe abrir, responder y procesar sin desesperar al usuario.

Seguridad

Debe proteger cuentas, contraseñas, transferencias y datos personales.

Rendimiento significa qué tan rápido y fluido funciona el software. Una aplicación puede tener buenas funciones, pero si tarda demasiado en abrir, se congela o responde lento, el usuario se desespera. Seguridad significa proteger la información del usuario. En una aplicación bancaria es fundamental porque maneja cuentas, transferencias, contraseñas y datos personales. Analogía: la seguridad es como la cerradura de una casa; si la casa es bonita pero no tiene cerradura, cualquiera puede entrar. Frase: "Un software sin seguridad puede poner en riesgo a la empresa y al usuario."
David

Confiabilidad

Un software confiable funciona correctamente la mayor parte del tiempo.

  • Google responde cuando lo necesitamos.
  • Como un carro que siempre arranca.
  • Si el usuario no confía, la calidad se pierde.
Estabilidad Pocas fallas Confianza Confiabilidad
Explicar que confiabilidad significa que el software funcione correctamente la mayor parte del tiempo. Usar Google como ejemplo: la mayoría del tiempo uno busca algo y espera que responda sin fallar. Analogía: es como un carro que siempre arranca; si un carro a veces enciende y a veces no, uno deja de confiar en él. Frase corta: "Si el usuario no confía en que el sistema funcione, la calidad se pierde."

No Man's Sky

WhatsApp

Agrega funciones nuevas porque el software puede mantenerse y evolucionar.

Explicar que mantenibilidad significa qué tan fácil es corregir, actualizar o mejorar el software. No Man's Sky sirve para explicarlo porque pudo mejorar con actualizaciones, correcciones y nuevas funciones. WhatsApp también agrega funciones nuevas con el tiempo. Analogía: es como construir una casa dejando espacio para remodelar; si todo está mal construido, cualquier cambio se vuelve difícil. Frase corta: "Un software de calidad debe poder mejorar sin romperse."
